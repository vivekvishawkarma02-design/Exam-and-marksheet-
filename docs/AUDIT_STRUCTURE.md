# App Structure, Settings & Data Connections Audit

**Scope:** Read-only code audit of `SchoolReportCardApp.kt` (`AppRoutes`), all UI screens, `SchoolViewModel` + phase extensions, domain engines, repositories, Room (`AppDatabase`), and `firestore.rules`. No app code, rules, tests, resources, or workflows were modified.

## 1. Screens and Navigation

### 1A. Navigation Shell & Structural Anomalies (`SchoolReportCardApp.kt`)
- **Top-level Bottom Bar / Rail (`buildWorkspaceTopNavItems`)**: Renders up to **6** items (`Home`, `Students`, `Marks`, `Reports`, `Members`, `Settings`), gated by view permission (`Settings` is always shown). Exceeds the 5-item Material guideline.
- **`isSubScreen` inconsistency (`SchoolReportCardApp.kt:671-688`)**: Only 18 of 27 secondary routes are listed in `isSubScreen`. **9 secondary screens** (`ROUTE_SCHOOL_SUBSCRIPTION`, `ROUTE_SALARY`, `ROUTE_SESSION_PROMOTION`, `ROUTE_BULK_IMPORT`, `ROUTE_BACKUP_EXPORT`, `ROUTE_CLASS_DIARY`, `ROUTE_BIRTHDAYS`, `ROUTE_STUDENT_REMARKS`, `ROUTE_GATE_PASS`) keep the bottom NavigationBar / NavigationRail visible while the other 18 hide it.
- **`SchoolSwitcherBar` stacking**: Shown on every route except `ROUTE_SCHOOLS`, `ROUTE_TEACHER_PROFILE`, and `ROUTE_DESIGN_PREVIEW`, so sub-screens display the school switcher bar above their own `TopAppBar`.
- **Broken scroll index in Settings (`SettingsScreen.kt:166`)**: `focusBackupSection` scrolls to hardcoded item index `6` (now the **Subjects** card) instead of the **Backup** card because cards `0.75`, `2.5`, and `2.75` were inserted above it.
- **No-op Home KPI tile**: Teacher Today hero card `"My Exam Duties"` (`Phase13TodayHomeComponents.kt:1148`) has `onClick = {}` (dead tap).

### 2C. Proposed 8 Clean Settings Groups
1. **School Profile**: School name, address, mobile, email, logo (`SchoolsScreen`), Birthday module toggle/templates (`SchoolBirthdayConfig`).
2. **Academic Year, Classes & Subjects**: Active/New session (`CloudOrgSettings`), School calendar & holidays (`schoolCalendars`), Class groups/classes (`schools.classes`), Class promotion order (`schoolClassOrders`), Subjects per group (`schools.classGroups`), Timetable period structure & subject rules (`periodStructures`, `subjectRules`).
3. **Members & Permissions**: Link/shortcut to `MembersScreen`, teacher scopes (`teacherScopes`), class teacher edit days limit (`schools.classTeacherAttendanceDaysBack`), teacher open-exam gates (`schools.openExamsForTeachers`), teacher salary self-view toggle (`salaryRuleConfigs.teacherCanViewOwnSlips`).
4. **Fees, Money & Transport**: Fee structure & concession approval limit (`feeStructures`), Fee WhatsApp templates (`feeMessageTemplates`), Cash Book opening balance/categories/approval limit (`cashBookSettings`), Transport expense categories (`transportSettings`), Salary deduction rules (`salaryRuleConfigs`).
5. **Exams, Attendance & Reports**: Pass %, unified 10/30/60 reference, show photo/admNo on Annual, show class rank, print class teacher name on reports, "report cards ready" check, auto-fill report attendance from daily attendance, remark categories (`studentRemarkCategories`).
6. **Appearance & Language**: Theme mode (`Light`/`Dark`/`System`), `Simple look` (blur toggle), App display language (`Hindi / English` labels).
7. **Data, Backup & Imports**: ZIP Full Backup (`Phase14BackupExportScreen`), JSON Backup/Restore + Legacy migration (`SettingsScreen`), Bulk Student Import (`Phase14BulkImportScreen`), Marks CSV Import/Template (`MarksCsvImportController`), On-phone Room data upload (`LocalDataMigrationDialog`).
8. **Account, Subscription & Legal**: Active Organisation & Switch Org, Sign Out, Leave/Delete Org, Delete Account, Remove Ads Subscription & Rewarded Ad-free status, Privacy & Ad Choices, Privacy Policy / Terms / Support / Version About.
- **Items that do not fit production Settings**: `Sample Preview Data` (belongs in onboarding/setup wizard or debug tools) and `Debug Ads Simulation` / `Design Preview` (`BuildConfig.DEBUG` developer drawer).

## 7. Risks for Changing This

1. **Existing Production Data & Schema Compatibility**:
   - Live Firestore data under `organisations/{orgId}` keys `marks`, `markEditLogs`, `classAssignments`, `timetableCells`, `teacherScopes`, `feeStructures.tuitionByClassAndMonth`, `studentAttendanceSheets`, and `examSchedules` by **string `className` and `subjectName`**, and keys `birthdayWishes` / `excludedStudentKeys` by `admNo`. Switching directly to IDs without fallback readers would break historical marks, fee structures, and report cards across old sessions (`2025-2026`, `2026-2027`).
   - Historical sessions must remain readable (`Phase14SessionPromotionScreen` allows switching to past sessions).
2. **Offline Sync & `firestore.rules` Constraints**:
   - **Rules Size Limit**: Compiled `firestore.rules` was recently shrunk to stay below Firestore's **256,000-byte** deploy limit; adding complex multi-document `get()` chains or new collections risks hitting the rules size limit or per-request 10-`get()` evaluation limit.
   - **Teacher Scope Enforcement (`firestore.rules`)**: Rules validate teacher writes to `marks`, `coScholastic`, and `termInfo` by reading `studentDoc.data.className` & `studentDoc.data.section` and matching against `teacherScopes/{uid}.assignedScopes` strings (`schoolId|className|section|subject`). Removing `className`/`section` from `students` or changing `subjectName` format without updating `teacherScopes` and rules would immediately block teacher edits with `PERMISSION_DENIED`.
   - **Offline Cache & Multi-Batch Writes**: Client runs offline-first with a 150 MB Firestore disk cache and `OfflinePrefsStore` pending queues (`pending_marks`, `pending_timetable`, `pending_phase6`). Cross-document fan-out updates (e.g., cascade-renaming `subjectName` across 500+ marks/timetable docs) done client-side while offline can partially commit or exceed 500-op Firestore `WriteBatch` limits unless batched cleanly (`batch.chunked(400)`).
   - **No Blaze Cloud Functions**: Project is on Spark / rules-only deploy (`deploy-firebase.yml` defaults to `rules-only`); server-side cascade triggers are not available today, so cascade fixes or ID-lookup reads must run safely on the client.
3. **Immutable Financial & Legal Documents (MUST NEVER BE MUTATED POST-ISSUE)**:
   - **`feeReceipts`**: Explicitly append-only / cancel-only (`firestore.rules` + audit trail). Printed/shared receipt numbers, `studentName`, `className`, `fatherName`, `lineItems`, and amounts are legal financial snapshots—never update them when a student or fee structure changes.
   - **`cashBookDayClosings` & `cashBookAuditLogs` / `feeAuditLogs` / `salaryAuditLogs` / `markEditLogs`**: Audit-protected records and closed cash-book days must stay immutable.
   - **`schoolCertificates`**: TC / Bonafide / Character certificates and their serial numbers are legal documents representing student state at issuance date—never auto-rewrite on later student edits.
   - **`promotionRecords` / `sessionTransitions`**: Historical session transition logs & PDF registers must remain frozen snapshots.
   - **Generated PDFs**: Existing Report Card, Fee Receipt, Certificate, and Gate Pass PDF layouts must keep exact visual output and stored values.
